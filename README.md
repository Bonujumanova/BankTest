# BankTest — API-автотесты

Проект по автоматизации тестирования REST API банковского приложения с использованием **Python, Pytest и Requests**.

В проекте реализованы API-автотесты для проверки пользователей, банковских счетов и кредитных операций.

## 🛠 Технологии

* **Python**
* **Pytest**
* **Requests**
* **Pydantic**
* **REST API**
* **Swagger**
* **Docker**
* **Allure**
* **Git / GitHub**

---

## 📌 Что тестируется

### 👤 Пользователи

Автоматизированы сценарии работы с пользователями:

* создание пользователя;
* получение списка пользователей;
* авторизация;
* проверка ролей пользователей;
* проверка прав доступа;
* негативные сценарии.

Используются роли:

* `ROLE_ADMIN`
* `ROLE_USER`
* `ROLE_CREDIT_SECRET`

### 💳 Банковские счета

Проверяются операции:

* создание банковского счёта;
* пополнение счёта;
* проверка баланса;
* проверка допустимых значений суммы;
* проверка ограничений количества счетов;
* обработка ошибок API.

### 💰 Кредиты

Проверяются:

* создание заявки на кредит;
* передача параметров кредитной заявки;
* получение истории кредитов;
* проверка кредитного баланса;
* бизнес-ограничения;
* негативные сценарии.

### Request Models

Для описания тела HTTP-запросов используются **Pydantic-модели**.

Например, данные для создания пользователя или пополнения счёта описываются отдельной моделью.

Это позволяет:

* явно описывать структуру запроса;
* проверять типы данных;
* использовать повторно подготовленные модели;
* преобразовывать модели в JSON.

Для передачи данных в API используется:

```python
model.model_dump()
```

---

## 📥 Response Models

Ответы API также описываются с помощью Pydantic.

Полученный JSON преобразуется в соответствующую модель:

```python
response_model = ResponseModel.model_validate(response.json())
```

Это позволяет проверять структуру ответа и работать с его данными как с Python-объектом.

## 🔐 Авторизация

Для авторизованных запросов используется JWT-токен.

Авторизация выполняется через endpoint:

```text
POST /auth/token/login
```

После успешной авторизации токен добавляется в HTTP-заголовок:

```text
Authorization: Bearer <token>
```

Для этого в проекте используется `RequestSpecs.authorization_headers()`.

Также предусмотрены заголовки для:

* авторизованных запросов;
* неавторизованных запросов;
* базовых HTTP-запросов.

---

## 📋 RequestSpecs

`RequestSpecs` содержит общую логику подготовки HTTP-запросов.

Основные задачи:

* создание базовых headers;
* получение JWT-токена;
* формирование authorization headers;
* подготовка headers для неавторизованных запросов;
* получение `base_url` из конфигурации.

Это позволяет не дублировать одну и ту же логику в каждом тесте.

---

## ✅ ResponseSpecs

`ResponseSpecs` используется для проверки HTTP-ответов.

Например:

```python
response_spec(response)
```

В проекте предусмотрены проверки различных ожидаемых статус-кодов:

* `200 OK`
* `201 Created`
* `400 Bad Request`
* и другие ответы API.

Таким образом, проверка HTTP-статуса отделена от непосредственной отправки запроса.

---

## 🌐 Requester

Requester-классы отвечают непосредственно за выполнение HTTP-запросов.

Например:

```
POST
GET
DELETE
```

Requester получает:

* URL;
* headers;
* request model;
* response specification.

После выполнения запроса производится проверка ответа, а затем при необходимости JSON преобразуется в соответствующую Pydantic-модель.

## 🧪 Позитивные и негативные тесты

В проекте используются оба типа сценариев.

### Позитивные сценарии

Проверяется корректное выполнение API-запроса при валидных данных.


### Негативные сценарии

Проверяется поведение API при некорректных данных.

Например:

* недопустимая сумма пополнения;
* отсутствие обязательного параметра;
* отсутствие авторизации;
* превышение бизнес-ограничений;
* повторное выполнение запрещённой операции.

## ▶️ Запуск проекта

Клонировать репозиторий:

```bash
git clone https://github.com/Bonujumanova/BankTest.git
cd BankTest
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать его.

### Linux / macOS

```bash
source .venv/bin/activate
```

Установить зависимости:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Запустить тесты:

```bash
pytest
```
